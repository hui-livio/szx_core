# 单项目 RABC 后端设计

## 1. 模块

- `auth`：登录、刷新、登出、改密、锁定。
- `user`：用户 CRUD、状态和单角色分配。
- `behavior-log`：行为/审计日志写入与查询。
- `policy`：按固定角色执行接口校验。

首版单体服务即可。Controller 负责协议，Service 负责规则和事务，Repository 使用参数化 SQL。

## 2. 固定角色策略

后端内置角色能力矩阵，不允许运行时编辑：

| 能力 | 操作员 | 工程师 | 管理员 | 超管 |
|---|---:|---:|---:|---:|
| 业务查看/操作 | ✓ | ✓ | ✓ | ✓ |
| 工程配置/诊断 |  | ✓ | ✓ | ✓ |
| 用户 CRUD |  |  | ✓ | ✓ |
| 管理员角色分配 |  |  |  | ✓ |
| 系统初始化/重置 |  |  |  | ✓ |

用户只有一个角色，采用固定映射；后续增加动态权限时再替换 Policy 实现。

## 3. 认证与审计

Argon2id 密码哈希，access JWT 15 分钟，refresh token 轮换。登录、改密、用户 CRUD、角色变更、禁用和关键 Client 业务事件写入 `user_logs`。日志异步写入可选，但关键安全审计必须可靠落库。

后端按用户固定角色计算能力码，例如 `business.read`、`business.operate`、`engineering.configure`、`user.manage`，通过 Client 接口返回；能力列表不由客户端提交，角色变更后按最新用户记录计算。

## 4. 安全规则

管理员不能创建或修改超管；只有超管可以分配管理员/超管角色。禁止删除最后一个超管。所有写操作使用事务和 `version` 防止并发覆盖。
