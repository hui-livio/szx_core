# 软授权工具首版实现说明

当前已落地 `szx::license` 和内部工具 `szx_license_issuer`，采用离线签名许可证流程：

```text
createRequest -> .szxreq -> szx_license_issuer issue -> .szxlic -> verify
```

## 库接口（客户侧）

- `createRequest(RequestOptions)`：生成 UTF-8 JSON 请求内容；支持产品、版本、请求功能和自定义字段。
- `verify(envelope, publicKeyDer, expectedProduct)`：校验 issuer key ID、签名、产品和有效期，并返回 `LicenseInfo`。
- `hasFeature`：检查已签发功能码。

签发函数位于未安装的 issuer 内部头文件中，仅供发行工具使用。

`IssueOptions::expiresAtUtc` 为空表示无限期；设置 Unix UTC 秒数表示指定失效时间。`issuer`、`issuedAtUtc` 和 `customFields` 会保留在签名 payload 中，但不会影响签名验证流程。

## CLI

客户端请求文件 demo（客户端只需要发行方公钥，不接触私钥）：

```text
szx_license_request_demo --product szx.crypto-tool --version 1.0 --public-key issuer-public.pem --output machine.szxreq
```

该 demo 使用 `createRequestFile` 采集并绑定机器因子，生成加密的 `.szxreq` 文件。请求文件应发送给发行方签发；demo 不输出原始机器标识、机器因子哈希或密钥内容。

```text
szx_license_issuer keygen --private-key issuer-private.der --public-key issuer-public.der
szx_license_issuer key-info --public-key issuer-public.der
szx_license_issuer request --product szx.crypto-tool --version 1.0 --public-key issuer-public.der --output machine.szxreq
szx_license_issuer issue --request machine.szxreq --private-key issuer-private.der --public-key issuer-public.der --output customer.szxlic --license-id lic-001 --issuer internal --days 365
szx_license_issuer verify --input customer.szxlic --public-key issuer-public.der --product szx.crypto-tool
```

签发私钥只通过受控文件路径读取，不作为命令行参数内容传递；issuer 工具应保持在内部发行环境，不纳入客户安装包。

`request` 使用签发方 RSA 公钥包装随机 AES-256-GCM 会话密钥，req 文件本身是认证加密的二进制封装，无法在不知道签发私钥的情况下修改后继续解密。`issue` 使用对应私钥解密 req，再校验机器因子并签发许可证。工具支持导入用户自行生成和保管的 RSA DER 或 PEM 密钥对，会自动将 PEM 转为 DER，并在签发前校验公私钥匹配。加密 PEM 私钥暂不支持，需先在受控发行环境解密后使用。

当前已实现机器因子采集：Windows 使用 SMBIOS UUID、MachineGuid 和系统卷序列号，Linux 使用 `/etc/machine-id`；原始标识经过产品域隔离后计算 SHA-256，仅将因子类型和哈希写入请求/许可证。验签时要求许可证中的因子全部不重复，因子数不超过两个时全部匹配，超过两个时至少匹配两个本机因子。许可证安装存储、时钟回拨保护和 issuer 多公钥轮换仍属于后续授权策略实现范围。
