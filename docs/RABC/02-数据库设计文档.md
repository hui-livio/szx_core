# 单项目 RABC 数据库设计

## 1. 设计原则

首版不建立 `projects`、`project_members`、`role_permissions` 等多项目或动态权限关联表。系统部署即代表一个项目，用户表中的 `role` 直接表示其项目角色。

## 2. 核心表

### users

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID/INTEGER | 主键 |
| `uid` | varchar | 业务用户唯一标识 |
| `username` | varchar | 登录名，唯一 |
| `display_name` | varchar | 展示名称 |
| `password_hash` | varchar | Argon2id 哈希 |
| `role` | enum | operator/engineer/admin/super_admin |
| `status` | enum | active/disabled/locked |
| `version` | int | 乐观锁版本 |
| `last_login_at` | timestamp | 最近登录时间 |
| `created_at/updated_at` | timestamp | 时间字段 |

约束：`uid` 和 `username` 全局唯一；创建用户时二选一作为外部身份标识（另一字段可由系统生成）；每个用户只有一个固定角色。

### refresh_tokens

保存 `token_hash`、`user_id`、`expires_at`、`revoked_at`，不保存 token 原文。

### user_logs

追加写入用户行为和安全审计：`id、user_id、event_name、result、request_id、ip、user_agent、details_json、created_at`。日志不可通过业务 API 修改或删除。

## 3. 建表示例

```sql
CREATE TABLE users (
  id uuid PRIMARY KEY,
  uid varchar(64) UNIQUE,
  username varchar(64) UNIQUE,
  display_name varchar(128) NOT NULL,
  password_hash varchar(255) NOT NULL,
  role varchar(16) NOT NULL CHECK (role IN ('operator','engineer','admin','super_admin')),
  status varchar(16) NOT NULL DEFAULT 'active', version int NOT NULL DEFAULT 1,
  last_login_at timestamptz, created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  CHECK (uid IS NOT NULL OR username IS NOT NULL)
);
CREATE INDEX idx_user_logs_user_time ON user_logs(user_id, created_at);
```

## 4. 后续扩展

未来需要细粒度权限时，再增加 `permissions`、`roles`、`role_permissions` 或权限组表；不修改首版角色语义即可迁移。
