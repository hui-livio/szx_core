# SZX 软授权开发方案（提案）

状态：目标设计；当前可执行实现已落地，协议扩展仍待产品、安全和开发负责人评审

日期：2026-09-02

本文只冻结候选方案，不代表授权协议已经发布，也不授权发行私钥进入仓库或测试资产。

当前实现以 [软授权工具实现说明](../RBAC/09-软授权工具实现说明.md) 和
`components/license/include/SzxLicense/License.h` 为准，已提供
`szx_license_user_demo` 客户端请求 demo、`szx_license_issuer` 内部签发 CLI 和
`szx_license_issuer_gui` 图形工具。本文中的 `inspect`、`validate`、`install`、
在线时间和密钥轮换等内容仍是后续设计，不应视为已发布能力。

## 1. 目标与边界

目标是交付离线优先的软授权能力：客户侧认证库、Windows 核心密码能力、独立机器信息/请求工具，以及仅供内部使用的授权签发工具。

P0 包含：

- AES-256-GCM 对称加密；
- RSA-OAEP-SHA256 混合加密所需的密钥包装能力；
- RSA-PSS-SHA256 签名与验签；
- `.szxreq` 授权请求和 `.szxlic` 签名许可证；
- Trial、Term、Perpetual 三种授权类型；
- 产品、应用版本、有效期、机器因子和 feature 校验；
- 客户侧 `FeatureGate` 快照；
- CLI 机器 ID、请求生成、inspect、verify、validate；
- 内部 issuer 的签发能力和客户包隔离。

P1 暂不纳入：在线激活、浮动授权、实时吊销服务、正式 TPM/HSM/PKCS#11、Linux provider、Maintenance 授权和网络时间票据。

## 2. 信任边界

```text
客户程序 -> szx::license -> szx::crypto_service -> 平台 provider
                                      ^
内部 issuer --------------------------+
```

- 发行私钥只存在于内部 Windows CNG 密钥存储或受控发行环境。
- 客户端只内置一个或多个发行公钥及 key ID。
- 授权签名密钥和文件加密密钥不得复用。
- 许可证内容不视为 secret；完整性和真实性由签名保证。
- 客户端认证库必须 fail closed，不能由 UI 或调用方自行解释 payload。

## 3. 协议提案

### 3.1 `.szxreq`

使用 UTF-8 JSON，字段如下：

```json
{
  "schema_version": 1,
  "request_id": "UUID",
  "product_id": "szx.crypto-tool",
  "app_version": "0.1.0",
  "machine_factors": [
    {"type": "machine_guid", "hash": "sha256"},
    {"type": "system_volume", "hash": "sha256"},
    {"type": "smbios_uuid", "hash": "sha256"}
  ],
  "requested_features": ["crypto.symmetric", "crypto.asymmetric"],
  "created_at": "UTC timestamp",
  "nonce": "base64url"
}
```

请求文件不提供授权，不包含原始硬件序列号、私钥、密码或用户文件信息。

### 3.2 `.szxlic`

使用版本化二进制 envelope：

```text
magic                 SZXL
schema_version        u16
signature_algorithm   u16   # RSA-PSS-SHA256
issuer_key_id         bytes # SHA-256(public key)
payload_size          u32
payload               bytes # canonical UTF-8 JSON
signature_size        u32
signature             bytes
```

签名覆盖 `header_without_signature || payload_original_bytes`。解析顺序固定为长度限制、版本/算法、key ID、签名、JSON、业务字段；签名成功前的 payload 不得用于功能决策。

## 4. 机器绑定提案

P0 因子：Windows `MachineGuid`、系统卷标识/序列号、SMBIOS System UUID。每个因子先使用 `szx-license-v1:<factor-type>:` 域分离，再计算 SHA-256。默认三个因子至少匹配两个。

需要明确处理：主板更换、系统盘更换、镜像克隆、虚拟机迁移和用户主动迁移授权。禁止因匹配失败而静默放宽规则。

## 5. 客户侧 API 提案

`szx::license` 对外只暴露 typed DTO、稳定错误码和 `Result<T>`：

- `createRequest`
- `inspect`
- `verify`
- `validate`
- `install`
- `hasFeature`
- `snapshot`

建议错误状态：`Missing`、`Malformed`、`UnsupportedVersion`、`SignatureInvalid`、`WrongProduct`、`WrongMachine`、`NotYetValid`、`Expired`、`VersionNotAllowed`、`ClockRollbackSuspected`。

## 6. 工具边界

当前已实现命令：

```text
szx_license_user_demo request --product <id> --version <ver> --public-key <der|pem> --output <req>
szx_license_user_demo verify --input <lic> --public-key <der|pem> [--product <id>]
szx_license_issuer keygen --private-key <pem> --public-key <pem> [--force]
szx_license_issuer issue --request <req> --private-key <der|pem> --public-key <der|pem> --output <lic> [--days <n>]
szx_license_issuer key-info --public-key <der|pem>
szx_license_issuer verify --input <lic> --public-key <der|pem> [--product <id>]
```

目标命令（尚未全部实现）仍保留如下：

客户工具：

```text
szx-license machine-id
szx-license request
szx-license inspect --input <file>
szx-license verify --input <file>
szx-license validate --input <file>
```

内部 issuer：

```text
szx-license-issuer keygen
szx-license-issuer issue --request <file> --output <file>
szx-license-issuer verify --input <file>
```

私钥不得通过命令行传入；issuer target、签发私钥和签发 API 不进入客户安装包。

## 7. 验收证据

协议：字段表、canonical 样本、版本策略、篡改/截断拒绝测试。

密码库：AES-GCM、RSA-OAEP、RSA-PSS 独立标准向量；错误 tag、错误签名、错误 key 的稳定错误码。

认证库：请求生成、签发、安装、验签、有效期/版本/机器/feature 校验和 FeatureGate 闭环。

工具：机器 ID 输出、`.szxreq` 生成、issuer 签发、客户 verify/validate、稳定退出码。

发布：客户包不包含 issuer、发行私钥或 OpenSSL 依赖。
