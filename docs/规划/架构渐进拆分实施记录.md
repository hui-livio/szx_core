| 验证计划 | 检查器自测、仓库边界检查、相关 CTest、完整编译和全量 CTest |
| 回滚方式 | 独立撤销阶段 0 提交 |

### 当前保护规则

1. 通用组件不得依赖 PCB 应用或 PCB 检测引擎。
2. 算法叶子节点不得依赖 Qt UI 或 UI 服务契约。
3. Engine 公共 API 不得暴露 Qt、数据库、算法和流程实现头。
4. UI Controller 不得绕过应用适配层直接依赖数据库或算法实现。

规则只冻结当前已经满足的依赖方向，不把现存的 `UiTypes`、Adapter 或数据库门面技术债设置为失败项；这些债务由后续阶段逐步收缩。

当前基线豁免：`MainWindowController.cc` 直接包含 `Detection/PcbDetectionConfig.h`。该依赖已登记为阶段 4 Adapter 拆分的迁移项；检查器只允许这一精确文件与头文件组合，不允许新增同类依赖。

### 修改后 Review

- 实际改动：新增 4 条依赖边界规则、检查器自测、2 项 CTest 和本实施记录。
- 计划偏差：发现 `MainWindowController.cc` 已直接依赖 `Detection/PcbDetectionConfig.h`；未扩大范围修改生产代码，改为精确基线豁免并登记阶段 4 清理。
- 影响复核：未修改生产目标、公共接口、QML、DTO、数据库或算法；CMake 仅在 `SZX_BUILD_UT=ON` 时注册测试。
- 风险发现：无未处理高风险；低风险为 Python 缺失时架构测试被禁用，CMake 会输出明确警告。
- 验证结果：检查器自测通过，4 条边界规则通过，`PCBDetect` 编译通过，608 项 CTest 全部通过。
- 结论：允许提交并进入阶段 1。
