# 工具与基础组件构建使用指南

本文是 `szx_core` 的统一构建入口，面向需要编译基础组件、运行测试或使用仓库工具的开发人员。模块 API 和专项配置仍以各模块文档为准；本文只说明仓库级构建、目标和运行方式。

## 1. 工程分层

| 目录 | 内容 | 典型目标 |
|---|---|---|
| `components/` | 可复用基础组件和公共 CMake targets | `szx::common`、`szx::crypto`、`szx::network`、`szx::camera`、`szx::plc` |
| `tools/` | 可执行工具和服务，不作为业务库发布 | `szx_admin_service`、`szx_license_issuer`、`szx_license_user_demo`、`UIToolkitsApp` |
| `tests/` | GoogleTest/CTest 测试和工具回归脚本 | `test_*`、`ctest` |

工具与基础组件在同一个顶层 CMake 工程中构建。作为子项目集成时，默认关闭测试、安装、工具演示和可选硬件依赖；需要这些能力时必须由宿主工程显式打开对应选项。

## 2. 最小构建

Windows 推荐在已加载 Visual Studio 2022 x64 开发环境的 PowerShell 中执行。Ninja Multi-Config 不依赖 Visual Studio 解决方案文件：

```powershell
cmake -S . -B build/msvc -G "Ninja Multi-Config" `
  -DSZX_COMPONENTS_BUILD_NETWORK=OFF `
  -DSZX_COMPONENTS_BUILD_WEB_IMAGE_TEST=OFF `
  -DSZX_COMPONENTS_BUILD_RBAC=OFF `
  -DSZX_COMPONENTS_BUILD_CAMERA=OFF `
  -DSZX_COMPONENTS_BUILD_PLC=OFF `
  -DSZX_COMPONENTS_BUILD_UI_TOOLKITS=OFF `
  -DSZX_COMPONENTS_BUILD_UI_TOOLKITS_APP=OFF
cmake --build build/msvc --config Release --parallel
ctest --test-dir build/msvc -C Release --output-on-failure
```

不需要服务和硬件 SDK 时关闭 Network、WebImageTest、RBAC、camera、PLC 可以减少本机依赖。WebImageTest 默认开启并要求 OpenCV 开发包；关闭 Network 时也需关闭 WebImageTest。独立构建默认启用基础测试、安装规则以及部分可选组件；配置结束时查看 CMake summary，确认实际启用项。

Linux/macOS 使用相同的 `cmake -S/-B` 和 `cmake --build` 命令。厂商相机 SDK、Windows CNG 相关能力和部分运行时依赖按平台可用性选择性启用。

## 3. 常用构建选项

| 选项 | 独立构建默认值 | 用途 |
|---|---:|---|
| `SZX_COMPONENTS_BUILD_NETWORK` | ON | HTTP/TCP/WebSocket 网络组件，Admin 和 WebImageTest 必需 |
| `SZX_COMPONENTS_BUILD_WEB_IMAGE_TEST` | ON | `szx_web_image_test` 图片示例，要求 Network 和 OpenCV |
| `SZX_COMPONENTS_BUILD_RBAC` | ON | `szx_admin_service` 后端，要求 Network |
| `SZX_COMPONENTS_BUILD_TESTS` | ON | 构建并注册 CTest 测试 |
| `SZX_COMPONENTS_INSTALL` | ON | 生成安装树和 `SZXComponents` package |
| `SZX_COMPONENTS_BUILD_CAMERA` | ON | 相机核心及可用厂商适配器 |
| `SZX_COMPONENTS_BUILD_PLC` | ON | 检测到 libmodbus 时构建 PLC |
| `SZX_COMPONENTS_BUILD_FEATURE_MANAGER` | ON | Feature Manager |
| `SZX_COMPONENTS_BUILD_FEATURE_MANAGER_QT` | OFF | Qt 6 Feature/QML 适配器 |
| `SZX_COMPONENTS_BUILD_UI_TOOLKITS` | ON | Qt 6/QML UI 工具包 |
| `SZX_COMPONENTS_BUILD_UI_TOOLKITS_APP` | ON | `UIToolkitsApp` 演示工具，要求 UI Toolkits |
| `SZX_COMPONENTS_BUILD_COMPRESSION` | 按源码 | ZIP/Zstandard 压缩栈 |
| `SZX_COMPONENTS_BUILD_IKAP` | OFF | IKap SDK 适配器 |
| `SZX_COMPONENTS_BUILD_HUARAY` | ON | 检测到 SDK 时构建华睿适配器 |

作为子项目时建议明确设置：

```cmake
set(SZX_COMPONENTS_BUILD_TESTS OFF CACHE BOOL "" FORCE)
set(SZX_COMPONENTS_INSTALL OFF CACHE BOOL "" FORCE)
set(SZX_COMPONENTS_BUILD_RBAC OFF CACHE BOOL "" FORCE)
set(SZX_COMPONENTS_BUILD_UI_TOOLKITS OFF CACHE BOOL "" FORCE)
add_subdirectory(external/szx_core)
```

需要 Admin 时同时打开 `SZX_COMPONENTS_BUILD_NETWORK=ON` 和 `SZX_COMPONENTS_BUILD_RBAC=ON`；需要 GUI 时使用 Qt 6.8 或更高版本。

## 4. 基础组件与安装消费

基础 targets 通过 `szx::` 命名空间导出：

```text
szx::common              基础类型和序列化
szx::crypto              密码原语
szx::crypto_service      统一加密服务门面
szx::logger              日志封装
szx::network             HTTP/TCP/WebSocket
szx::license             软授权库
szx::camera              相机生命周期和采集管道
szx::plc                 PLC 控制
szx::feature_manager     Feature 配置和 Provider
szx::compression         ZIP/压缩门面
UIToolkits               Qt 6/QML 控件（可选）
```

安装并在其他工程中使用：

```powershell
cmake -S . -B build/msvc -G "Ninja Multi-Config" -DSZX_COMPONENTS_INSTALL=ON
cmake --build build/msvc --config Release
cmake --install build/msvc --config Release --prefix C:/libs/szx_core
```

消费方：

```cmake
list(APPEND CMAKE_PREFIX_PATH "C:/libs/szx_core")
find_package(SZXComponents 0.1 CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE
    szx::common szx::crypto szx::crypto_service szx::logger)
```

不要直接链接第三方实现库；通过组件 target 获取 include、编译定义和传递依赖。相机/PLC/厂商 SDK 的路径和运行时 DLL 见[组件集成使用指南](组件集成使用指南.md)。

## 5. 工具与服务

### 5.1 Admin 服务

Admin 已初步完成：C++ 服务、认证/会话、用户管理、权限查询、安全审计、行为事件接口和 Vue 3 Admin 页面已接入同一服务，默认由 `/admin/` 托管，API 默认前缀为 `/api/v1`。当前阶段是联调和部署验收，不等同于所有业务 Client 已接入或生产 HTTPS 已完成。

先安装前端依赖，再构建服务；CMake 会自动执行前端构建并将最新 `dist` 复制到服务输出目录：

```powershell
Set-Location tools/szx_admin/web/admin
npm ci
Set-Location ../../../..
cmake --build build/msvc --config Release --target szx_admin_service --parallel
Set-Location build/msvc/bin/Release
./szx_admin_service.exe --config config/config.yaml
```

每次构建 `szx_admin_service` 都会执行 `npm run build`，即使后端无需重新链接也会刷新前端产物。自定义构建目录时，产物会复制到该构建树中的服务可执行文件目录；自定义 `server.staticRoot` 时，可在构建后直接调用 `scripts/deploy_admin_web.ps1 -StaticRoot <目录>`。

访问 `http://localhost:7364/admin/`；接口文档在 `http://localhost:7364/api/v1/`，健康检查为 `GET /api/v1/health`。首次启动的 bootstrap 账号为 `admin` / `superadmin`，首次登录必须改密。生产必须替换密钥、配置数据库，并通过 HTTPS 反向代理提供访问。

完整部署、配置、日常操作、Nginx 和排障见 [Admin 部署与使用指南](../RBAC/12-Admin部署与使用指南.md)。

### 5.2 软授权工具

软授权工具统一位于 `tools/license/`：

| 工具 | 用途 |
|---|---|
| `szx_license_user_demo` | 客户侧生成 `.szxreq` 和验证 `.szxlic` |
| `szx_license_issuer` | 内部密钥、签发和验证工具 |
| `szx_license_issuer_gui` | 内部 Qt/QML 签发界面 |

构建后可执行文件通常位于 `build/msvc/bin/Release/`。端到端回归：

```powershell
py -3 scripts/test_license_flow.py --build-dir build/msvc
```

CLI 参数和密钥边界见[软授权设计使用指南](软授权设计使用指南.md)及[软授权工具实现说明](../RBAC/09-软授权工具实现说明.md)。发行私钥不得进入客户包。

### 5.3 Qt UI 工具

使用 Qt 6.8+ 的 `qt-cmake` 或已配置 Qt 的 CMake 环境，并打开 `SZX_COMPONENTS_BUILD_UI_TOOLKITS=ON`。`SZX_COMPONENTS_BUILD_UI_TOOLKITS_APP=ON` 会构建 `tools/UIToolkitsApp/` 演示工具；它是工具，不是可复用组件。QML 生成缓存和 `.qmlls.ini` 不属于源码交付物。

## 6. 测试与格式化

```powershell
ctest --test-dir build/msvc -C Release --output-on-failure
pwsh -File scripts/format_cpp.ps1 -Mode Check
```

Admin 前端测试：

```powershell
Set-Location tools/szx_admin/web/admin
npm test
npm run test:e2e
npm run format:check
```

前端 E2E 使用模拟 API；不能替代真实 MySQL、HTTPS Cookie、密钥和生产反向代理验收。Admin 后端真实回归脚本及环境要求见 [基础能力开发计划](../RBAC/11-基础能力开发计划.md)。

## 7. 常见问题

| 问题 | 处理 |
|---|---|
| Admin target 不存在 | 重新配置并确保 `SZX_COMPONENTS_BUILD_NETWORK=ON`、`SZX_COMPONENTS_BUILD_RBAC=ON` |
| 前端页面 404 或空白 | 重新构建 `szx_admin_service`，确认可执行文件目录下的 `web/admin/index.html` 存在并重启首次部署的服务 |
| API 能访问但登录失败 | 检查数据库、JWT 密钥、Origin、HTTPS、Cookie 和 Web Crypto |
| Qt 工具未构建 | 检查 Qt 版本及 `SZX_COMPONENTS_BUILD_UI_TOOLKITS` 开关 |
| 压缩组件配置失败 | 提供完整 `third_party/zstd/build/cmake`，或关闭 `SZX_COMPONENTS_BUILD_COMPRESSION` |
| 厂商 DLL 找不到 | 将 SDK runtime 目录加入 `PATH`，详见组件集成指南 |
