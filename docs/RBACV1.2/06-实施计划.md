# RBAC V1.2 实施计划

## 1. 交付策略

采用“数据库目录与登录标识迁移 → 只读授权 → 切换现有鉴权 → 管理 API → Admin UI → 发布验收”的垂直切片。先证明无碰撞账号的登录、密码、角色和状态行为保持一致，再开放自定义角色和权限写操作。

预计工作量：约 28–38 人日，不含产品评审等待和生产发布窗口。建议 2 名开发并行（C++ 后端/数据库、Vue 前端），测试从第二个里程碑开始介入，历时约 4–6 周。

## 2. Definition of Ready

进入实现前必须确认：

- 本文档集完成产品、后端、前端、测试评审；
- 明确 V1.2 继续单项目、单用户单角色；
- 确认自定义权限只允许 client enforcement；
- 确认角色管理范围采用显式关系；
- 确认生产 migration 执行方式和备份责任人；
- 获取至少一份匿名化 V1.1 数据库副本或等价测试数据；
- 明确目标发布版本、Owner 和验收环境；
- 现有第一阶段测试在基线提交通过；
- OpenAPI、Admin 构建和 MySQL 8.0 测试环境可用。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| users.role 旧 CHECK 未正确移除 | 自定义角色无法分配 | information_schema 精确发现 + 真实旧库测试 |
| 旧 UID 仅大小写不同 | 新唯一规则产生碰撞 | 发布前碰撞报告 + 人工处置，migration 禁止自动合并 |
| 旧客户端依赖 uid/username | 创建或展示失败 | `/api/v1` 兼容适配、Deprecation Header、使用量监控 |
| 角色权限变化未失效旧 token | 越权窗口 | role_authz_version 每请求校验 |
| 只按权限不按 scope | 横向管理越权 | AuthorizationService 统一目标校验 |
| 自定义 server 权限无执行点 | 安全假象 | API 只允许 custom/client |
| super_admin 权限被误删 | 系统失去恢复能力 | required_for_super_admin + 事务校验 + readiness |
| 禁用权限更新大量角色 | 大事务/死锁 | 1000 角色上限、固定锁顺序、运维路径 |
| 前端仍按固定 role 分支 | 新角色页面异常 | 全库 `rg` + 类型替换 + E2E |
| V1.2 回滚至 V1.1 | V1.1 缺少新字段且依赖已删除旧列 | 数据库备份恢复，禁止只回滚二进制 |
| 多实例同时 migration | 冲突 | 沿用 advisory lock 和 checksum journal |
| DTO/C++ 公共结构 ABI 变化 | 外部消费者编译/运行失败 | M0 盘点；必要时新增版本化结构 |

## 9. Definition of Done

- 自定义角色和权限可通过 Admin 端到端创建、配置、使用和归档；
- 现有四角色迁移后权限行为无回归；
- 所有后端接口由数据库权限校验，无固定角色授权分支；
- 用户角色和角色权限变化按设计使旧会话失效；
- 超管安全底线、最后一个 active 超管和 manage scope 负例通过；
- migrations 在全新库、V1.1 库、部分 DDL 重试场景通过；
- 统一登录标识迁移零未处理碰撞，旧 uid/username 物理列已删除且 API 兼容测试通过；
- OpenAPI、Admin 类型、实现和测试一致；
- 相关 C++、前端、集成和 E2E 测试通过；
- 性能目标满足或有书面例外；
- 备份、发布、回滚演练完成；
- 部署、使用、接口和测试文档已同步；
- 无未处理 P0/P1 缺陷，延期风险有 Owner 和截止时间。

## 10. 第二阶段启动记录（2026-10-14）

本轮首先交付“自定义权限 + 为现有角色分配自定义权限”的垂直切片，不宣称整个 M1–M5 已完成。仓库已存在 migrations 6–11、动态授权仓储、角色/权限管理 HTTP 接口，本次在此基础上补前端和验证，不改写已发布 migrations，不连接实际业务库执行写入测试。

### 本轮范围

- 新增 `/permissions` 页面和权限控制导航；查询、搜索/来源过滤、包含归档、创建、编辑说明、启停和归档；内置权限只读。
- 超管默认拥有管理能力，前端入口按 `permission.read`、各写能力分别控制；后端每次请求仍进行数据库授权。
- 权限创建为 `source=custom/enforcement=client`，不支持管理 API 创建 server 权限；code/module 不可修改，不复用归档 code。
- 角色分配面板可分配启用的自定义权限、移除已有停用关联，保留当前系统关联，使用角色 If-Match；不暴露删除超管必需权限的交互。
- 修正权限创建响应 version=0、description 缺失及 ORM 更新 conflict-key 注册顺序；归档前检查角色绑定；补超管必需权限保护；新权限 DTO 用 iguana 序列化。
- 更新 Swagger 中既有角色与权限端点，覆盖 role/permission read/write，使用 V1.2 已定义的稳定 admin 码 2228/2230/2232/2233，不复用用户标识冲突码。
- 隔离数据库验证包括默认角色拒绝、生命周期、重复 code、并发重复、事务审计失败回滚、授权变更拒绝旧 token；浏览器验证覆盖 CRUD、冲突重新加载、分配、移动/暗色及无权限入口。

### 未纳入本轮／后续里程碑

- 自定义角色 CRUD 管理页、角色管理范围编辑、用户编辑器全面替换固定角色选项；当前新增界面可以为接口返回的角色分配权限，但不据此宣称所有自定义角色登录/导航/用户编辑场景已交付。
- 历史库匿名副本升级、迁移部分 DDL 重试、MySQL 最低版本实机矩阵、Windows 原生运行、双实例撤权、性能基准和正式发布/备份回滚演练。
- 本轮不新增 Deny、租户或多角色，不增加服务端权限动态路由保护。

### 首轮 review 修复

基线先提交为 `303b4d4`，随后处理三项 review：
