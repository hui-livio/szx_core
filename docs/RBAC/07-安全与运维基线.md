# RBAC 安全与运维基线

## 1. 密码与账户

- 密码使用 Argon2id；版本、内存、迭代次数、并行度和输出长度由部署配置冻结，并保留升级/re-hash 判断。
- 第一阶段默认 Argon2id 参数为 memory=64 MiB、iterations=3、parallelism=1、salt=16 bytes、output=32 bytes；生产发布前可提高但不得降低，参数变更触发 re-hash。
- 当前前端按角色校验新密码：operator/engineer 至少 6 个 Unicode 字符，可使用纯数字或纯字母；admin/super_admin 至少 8 个字符，必须同时包含字母和数字，不强制特殊字符。创建、重置按目标角色，自助改密按当前角色。服务端接收 64 位小写 SHA-256 摘要并经 Argon2id 存储，无法从摘要校验原始密码强度。
- 创建和重置密码可指定摘要；未指定则生成 20 字符临时密码，仅响应一次，默认 24 小时有效。指定密码不回显、不设置临时有效期，首次改密策略不变。
- 登录失败使用统一错误响应。默认连续 5 次错误密码使账号 locked，记录 900 秒锁定时间；到期不会自动解锁，需明确调用解锁接口。认证及凭据签发共用每 IP 每分钟 30 次预算，配置项为 `auth.attemptsPerMinute`；详见 API 文档限流表。
- 初始超管由启动阶段幂等创建，默认账号为 `admin`、初始密码为 `superadmin`，首次登录必须改密；密码仅以 Argon2id 哈希写入数据库。
- disabled/locked 账户拒绝登录和受保护请求；解锁、改密和重置密码都写入审计。
- 超管 `force_password_change=true` 时，后端禁止用户管理、审计查询、权限查询和行为上报（`403 / 2204`），不能通过跳过前端路由绕过。认证接口仍可用于登录、刷新、登出和修改自己的密码；改密成功后须重新登录。其他角色仍仅建议改密。
- 密码不得出现在 URL、日志、异常、审计 details、共享状态、浏览器持久化存储或 telemetry 中。表单输入和一次性凭据仅保留在当前交互内，关闭、成功或离开页面后清除。

## 2. Token 与密钥

- access JWT 有效期 15 分钟，固定使用 PS256；`iss` 和 `aud` 来自主程序统一加载的全局配置，客户端不能指定或覆盖。
- JWT 至少包含 `iss`、`aud`、`sub`、`jti`、`iat`、`nbf`、`exp` 和 `authz_version`；JWT header 必须包含 `kid`，用于密钥轮换。
- refresh token 使用高强度随机值，数据库只保存 hash；每次使用后轮换。
- refresh token 重放撤销整个 token family，并生成安全审计事件。
- 改密、角色变更、禁用和解锁统一通过 `authz_version` 立即影响旧 token；refresh family 另外执行会话撤销。
- 签名密钥不提交到代码仓库或日志，部署使用受控密钥来源；轮换时保留明确的旧密钥验证窗口。

## 3. 审计与日志

审计记录至少包含：

```text
actor_user_id, target_user_id, event_name, result,
request_id, ip, user_agent, created_at, details_json
```

审计事件包括登录成功/失败、改密、重置密码、refresh 轮换/重放、创建/编辑/启停用户、角色变更、锁定/解锁、权限拒绝和关键业务操作。

安全审计必须可靠落库。若审计写入失败，相关安全写操作必须回滚或返回明确失败；不能只记录到普通应用日志后继续返回成功。

Client 提交的 behavior event 只用于非可信业务 telemetry，不能作为安全审计事实来源。日志查询支持分页、时间范围、结果、`event_search`（事件代码/中文名称关键词）和 `actor_search`（展示名/用户名/UID），并执行脱敏。管理界面展示中文事件名及事件代码、操作者用户名；内部 UUID 只保留在 API 兼容字段中，不作为界面搜索条件。

## 4. 部署与网络

- Admin 页面通过 `/admin/` 与 `/api/v1` 同源提供，构建产物位于 `staticRoot/admin`；配置、数据库和密钥不得放入静态目录。部署及端口排查见 [Admin 部署与使用指南](12-Admin部署与使用指南.md)。
- 生产页面和所有 API 使用 HTTPS；反向代理、CORS、安全响应头和请求体大小限制写入部署配置。
- access token 通过 Authorization header 传递；浏览器 refresh token 使用 HttpOnly、Secure、SameSite Cookie，所有 Cookie 写操作配置 CSRF token；禁止无保护 localStorage。
- 数据库账号遵循最小权限；应用运行账号不能删除审计或行为表。保留期清理使用独立维护账号和受控命令。
- 数据库连接和密钥通过部署密钥管理，不写入仓库；bootstrap 不提供外部凭据配置。
- 记录应用版本、migration 版本、JWT key id、数据库版本和依赖 SBOM，便于回滚。
- 安全审计默认保留 180 天，客户端行为事件默认保留 30 天；保留期、归档位置和删除授权由运维配置冻结，任何清理操作必须单独审计。

## 5. 监控、备份与回滚

至少监控：登录失败率、账户锁定数、403/429 比例、refresh 重放、审计写入失败、数据库连接失败和 migration 失败。

发布前完成：

1. 数据库备份与恢复演练；
2. migration 向前/回滚演练；
3. 密钥轮换和旧 token 验证窗口演练；
4. 旧版本制品回滚演练；
5. 审计日志保留周期和访问权限确认。

所有部署和回滚操作必须关联 request/release 标识并写入运维审计。

## 6. Web 攻击防护与当前边界（2026-09-20）

| 攻击方式 | 当前防护 |
|---|---|
| SQL 注入 | 登录、用户查询、审计查询使用 MySQL prepared statement 参数绑定。排序由固定白名单选择；LIKE 搜索转义 `%`、`_` 和反斜杠，不将搜索文本拼入 SQL。不要用前端关键词黑名单替代参数绑定。 |
| XSS / 脚本注入 | Vue 文本插值转义；当前页面无 `v-html`/`innerHTML` 等用户输入 HTML 渲染入口。服务统一设置 CSP，仅允许同源脚本，不允许内联脚本和 eval，禁止插件、base 标签和外站连接。 |
| 点击劫持 / MIME 嗅探 | 静态页面、Swagger UI、API、重定向和错误响应均带 `frame-ancestors 'none'`、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`。 |
| 跨站请求 | 按跨域接入要求，`auth.allowedOrigin` 默认 `"*"` 接受 HTTP/HTTPS 来源，回显具体 Origin 并允许 credentials；可配置单一 Origin 限制来源，仍拒绝 `Origin: null`。refresh Cookie 使用 `HttpOnly; Secure; SameSite=None`；refresh/logout 校验 CSRF token。无 Origin 的原生客户端仍需正常 Bearer/CSRF 鉴权，CORS 不能替代授权。 |
| 越权 / 绕过页面 | 数据库当前角色、状态和 authz_version 决定授权；前端隐藏按钮不构成权限边界。后端拒绝强制改密超管的业务调用，禁止自己分配角色、禁用自己及管理更高权限用户。 |
| 令牌重放 / 暴力尝试 | refresh 轮换及会话族重放撤销；登录失败锁定、按 IP 限流。行为上报不做分钟限流，通过有界队列的 2225/2226 背压保护资源。 |
| 路径穿越 / 请求滥用 | 静态目录 confinement、请求体及连接数上限、JSON 字段白名单、分页和字段长度限制。 |

CSP 的 `style-src` 保留 `'unsafe-inline'`，兼容 Vue 动态样式和 Swagger UI；脚本策略不含 `'unsafe-inline'` 或 `'unsafe-eval'`。此外设置 `Referrer-Policy: no-referrer` 以及禁用相机、麦克风、地理位置的 `Permissions-Policy`。这是纵深防护，不能代替输出转义或使任意第三方脚本可信。

本轮没有改变以下部署风险，生产上线必须处理：仓库现有数据库凭据应视为已暴露并轮换，部署改用不入 Git 的受控配置；固定 bootstrap 初始密码应在隔离初始化阶段立即修改；Swagger/OpenAPI 仍公开，需在反向代理按网络来源限制；密码摘要是可用于登录的凭据，SHA-256 不能替代 HTTPS。服务只收到密码摘要，原始密码复杂度目前由前端检查，直接 API 客户端可绕过强度规则。

验证入口：`test_rbac_infra` 覆盖安全响应头、Origin 校验、请求限制与路径穿越；`scripts/test_admin_database.py` 在独立临时 MySQL 实例中验证 SQL 注入字符串、强制改密前后的 HTTP 权限、CSRF、重放、角色限制及事务回滚，不连接现有业务数据库。
