# 单项目 RBAC 数据库设计

## 1. 设计原则

第一阶段不建立 `projects`、`project_members`、`role_permissions` 等多项目或动态权限关联表。系统部署即代表一个项目，用户表中的 `role` 直接表示其项目角色。

第一阶段以 MySQL 8.0+ migration 作为数据库基线，使用 InnoDB、`utf8mb4` 和 UTC 时间。数据库访问统一使用 ormpp；应用层不得混用其他 ORM 或直接暴露 MySQL 客户端类型。MySQL Connector/C 或兼容的 MariaDB Connector/C 由构建环境提供，并通过明确的 CMake imported target 接入。migration SQL 只在构建阶段作为输入，编译为服务内置资源，运行时不读取本地 SQL 文件，也不将 migration 目录复制到发布包。

## 2. 核心表

### users

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | char(36) | UUID 字符串主键 |
| `uid` | varchar | 业务用户唯一标识 |
| `uid_canonical` | varchar | UID 规范化值，用于唯一索引和登录匹配 |
| `username` | varchar | 登录名，唯一 |
| `username_canonical` | varchar | 用户名规范化值，用于唯一索引和登录匹配 |
| `display_name` | varchar | 展示名称 |
| `password_hash` | varchar | Argon2id 哈希 |
| `role` | varchar + CHECK | operator/engineer/admin/super_admin |
| `status` | varchar + CHECK | active/disabled/locked |
| `version` | int | 乐观锁版本 |
| `force_password_change` | boolean | 首次登录或管理员重置后必须改密 |
| `temporary_credential_expires_at` | timestamp | 临时凭据过期时间；正式改密后清空 |
| `failed_login_count` | int | 连续登录失败次数 |
| `locked_until` | timestamp | 临时锁定截止时间，可为空 |
| `password_changed_at` | timestamp | 最近一次改密时间 |
| `disabled_at` | timestamp | 禁用时间，可为空 |
| `created_by` | char(36) | 创建者，可为空（bootstrap） |
| `authz_version` | int | 角色/状态/密码变更时递增，用于失效旧会话 |
| `last_login_at` | timestamp | 最近登录时间 |
| `created_at/updated_at` | datetime(6) | UTC 时间字段 |

约束：`uid` 保留用户输入的展示值，`uid_canonical` 执行 trim + Unicode NFC 规范化但保留大小写；`username` 保留展示值，`username_canonical` 执行 trim + Unicode NFC + locale-independent lowercase。数据库对 canonical 列建立唯一索引。创建用户时必须且只能持久化其中一个身份标识及其 canonical 值，二者均可作为登录 identifier；身份标识创建后不可修改。每个用户只有一个固定角色。进入 `locked` 时写入 `locked_until`，到期不自动转 active；明确解锁时清零失败计数并清空 `locked_until`。

### refresh_tokens

保存 `id、user_id、token_hash、family_id、replaced_by、created_at、last_used_at、expires_at、revoked_at、revocation_reason、ip、user_agent`，不保存 token 原文。refresh token 每次使用后轮换；同一 family 出现重放时撤销整个 family。

### user_logs

追加写入用户行为和安全审计：`id、actor_user_id、target_user_id、event_name、result、request_id、ip、user_agent、details_json、created_at`。`details_json` 禁止密码、token、私钥和原始机器标识。日志不可通过业务 API 修改或删除，关键审计事件必须与业务写操作处于同一事务。

## 3. 建表示例

应用启动前执行版本化 migration；使用 `schema_migrations(version, applied_at, checksum)` 记录已应用版本。migration 必须可审计，生产环境禁止应用进程自动执行未审核的破坏性变更。MySQL migration 必须显式声明 `ENGINE=InnoDB`、`DEFAULT CHARSET=utf8mb4` 和统一排序规则；`uid_canonical`、`username_canonical` 的规范化由应用层执行，数据库唯一索引负责最终约束。由于 MySQL DDL 可能隐式提交，migration 内容必须保持可重试、幂等；执行器只对 migration journal 写入提供事务保护，不能宣称跨 DDL 的原子回滚。建库使用 `CREATE DATABASE IF NOT EXISTS`，建表使用 `CREATE TABLE IF NOT EXISTS`，同一版本只能记录一次且 checksum 不可被覆盖。

默认超管不属于 SQL migration。migration 完成后由 bootstrap 服务在事务中按唯一用户名查询并加锁：不存在时创建 `role=super_admin`、`status=active`、`force_password_change=true` 的账号；已存在时保持原密码和业务状态，不重复插入或重置密码。首次登录改密成功后清除 `force_password_change`。

```sql
CREATE TABLE users (
  id char(36) PRIMARY KEY,
  uid varchar(64),
  uid_canonical varchar(64) UNIQUE,
  username varchar(64),
  username_canonical varchar(64) UNIQUE,
  display_name varchar(128) NOT NULL,
  password_hash varchar(255) NOT NULL,
  role varchar(16) NOT NULL CHECK (role IN ('operator','engineer','admin','super_admin')),
  status varchar(16) NOT NULL DEFAULT 'active' CHECK (status IN ('active','disabled','locked')),
  version int NOT NULL DEFAULT 1,
  force_password_change boolean NOT NULL DEFAULT true,
  temporary_credential_expires_at datetime(6),
  failed_login_count int NOT NULL DEFAULT 0,
  locked_until datetime(6),
  password_changed_at datetime(6),
  disabled_at datetime(6),
  created_by char(36),
  authz_version int NOT NULL DEFAULT 1,
  last_login_at datetime(6), created_at datetime(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  updated_at datetime(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),
  CHECK ((uid IS NOT NULL) <> (username IS NOT NULL)),
  CHECK ((uid IS NULL) = (uid_canonical IS NULL)),
  CHECK ((username IS NULL) = (username_canonical IS NULL)),
  CHECK (failed_login_count >= 0),
  CHECK (version > 0 AND authz_version > 0),
  CONSTRAINT fk_users_created_by FOREIGN KEY (created_by) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE refresh_tokens (
  id char(36) PRIMARY KEY,
  user_id char(36) NOT NULL,
  token_hash varchar(128) NOT NULL UNIQUE,
  family_id char(36) NOT NULL,
  replaced_by char(36),
  created_at datetime(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  last_used_at datetime(6),
  expires_at datetime(6) NOT NULL,
  revoked_at datetime(6),
  revocation_reason varchar(64),
  ip varchar(45),
  user_agent varchar(512),
  CONSTRAINT fk_refresh_tokens_user FOREIGN KEY (user_id) REFERENCES users(id),
  CONSTRAINT fk_refresh_tokens_replaced_by FOREIGN KEY (replaced_by) REFERENCES refresh_tokens(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
CREATE INDEX idx_refresh_tokens_user ON refresh_tokens(user_id, created_at DESC);
CREATE INDEX idx_refresh_tokens_family ON refresh_tokens(family_id);

CREATE TABLE user_logs (
  id char(36) PRIMARY KEY,
  actor_user_id char(36),
  target_user_id char(36),
  event_name varchar(96) NOT NULL,
  result varchar(16) NOT NULL CHECK (result IN ('success','failure','denied')),
  request_id varchar(128) NOT NULL,
  ip varchar(45),
  user_agent varchar(512),
  details_json json NOT NULL,
  created_at datetime(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
  CONSTRAINT fk_user_logs_actor FOREIGN KEY (actor_user_id) REFERENCES users(id),
  CONSTRAINT fk_user_logs_target FOREIGN KEY (target_user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
CREATE INDEX idx_user_logs_actor_time ON user_logs(actor_user_id, created_at DESC);
CREATE INDEX idx_user_logs_target_time ON user_logs(target_user_id, created_at DESC);
CREATE INDEX idx_user_logs_event_time ON user_logs(event_name, created_at DESC);
```

## 4. 后续扩展

未来需要细粒度权限时，再增加 `permissions`、`roles`、`role_permissions` 或权限组表；不修改第一阶段角色语义即可迁移。
