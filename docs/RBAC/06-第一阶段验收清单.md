# RBAC 第一阶段验收清单

## 1. 交付范围

第一阶段交付一个单项目、单体 RBAC 服务，包含：

- 一次性 bootstrap 超管初始化；
- 登录、刷新、登出、首次改密和自助改密；
- 用户创建、编辑、启用/禁用、锁定/解锁和密码重置；
- 操作员、工程师、管理员、超管四个固定角色；
- Admin 用户管理、日志查询和 Client 当前权限查询；
- 服务端鉴权、refresh token 轮换和安全审计；
- Vue Admin 页面和至少一条 Client 业务接口的端到端验证。

以下内容明确不在第一阶段：多项目、组织树、自定义角色、权限组、行级权限、SSO/MFA、在线吊销服务和复杂权限编辑器。

## 2. 功能验收

| 编号 | 验收条件 | 必须提供的证据 |
|---|---|---|
| F-01 | bootstrap 幂等初始化超管 admin，当前初始密码 superadmin；重复启动不重置密码，首次登录必须改密 | 初始化日志、重复执行结果、数据库记录 |
| F-02 | 超管首次登录必须改密；非超管首次登录提示且业务端允许跳过。临时凭据默认 24 小时有效，只展示一次；超管登录时消费，非超管保留原有效期；密码不以明文保存 | 分角色流程测试、API 测试、过期/重放测试、密码字段检查 |
| F-03 | `identifier` 可按 uid 或 username 登录；失败不泄露账号是否存在 | 登录正反例和错误响应 |
| F-04 | disabled/locked 用户不能登录或调用受保护接口；管理员只能解锁 operator/engineer，超管可解锁全部目标 | 集成测试 |
| F-05 | 四个角色按权限矩阵访问业务接口，审计查询能力只授予 admin/super_admin | 角色 × 接口正反向测试矩阵 |
| F-06 | 管理员只能管理 operator/engineer，包括解锁和密码重置；超管才能管理 admin/super_admin | API 403 测试和界面角色过滤 |
| F-07 | 不能禁用、降级或并发移除最后一个 active 超管 | 事务并发测试，返回 `LAST_SUPER_ADMIN_PROTECTED` |
| F-08 | 所有用户状态/密码/角色写操作使用 `If-Match`，冲突不覆盖更新 | 并发更新测试，返回 `CONFLICT_VERSION` |
| F-09 | refresh token 每次轮换，旧 token 重放撤销整个 family | token 生命周期和重放测试 |
| F-10 | 改密、角色变更、禁用后旧会话按 authz_version 失效 | 会话失效测试 |
| F-11 | 登录、改密、用户变更、角色变更、状态变更和重放事件都有审计记录 | 日志查询结果，含 actor/target/request_id |
| F-12 | 审计写入失败时安全操作不会静默成功 | 故障注入测试 |
| F-13 | 前端只使用权限结果改善体验，直接调用接口仍由后端拒绝 | 浏览器/API 联合测试 |
| F-14 | access token 临近过期或鉴权过期时按需刷新，并发合并；refresh 401/403 或 2202 清空内存会话，429/5xx 保留会话供手动重试 | 浏览器并发请求测试 |
| F-15 | CryptoService 提供 Argon2id hash/verify、PS256 sign/verify、key id/rotation 所需门面；RBAC 不直接依赖 OpenSSL/jwt-cpp | 公共头文件检查、Service 单测和 token 兼容测试 |
| F-16 | 创建/重置支持指定密码，留空随机；operator/engineer 至少 6 位，admin/super_admin 至少 8 位且含字母和数字 | 前端校验、摘要请求和凭据清理测试 |
| F-17 | 自己的角色分配和禁用操作被拒绝；高于自身或超出管理范围的目标不可操作 | UI 按钮状态和后端 403 测试 |
| F-18 | 审计按中文名称/事件代码关键词及展示名/用户名/UID 查询，筛选与 total 一致；不使用 UUID 搜索框 | API 查询、清空筛选和分页测试 |
| F-19 | 服务 `/admin` 跳转 `/admin/`，页面、资源及子路由刷新正常；API、缺失资源和路径穿越不回退到 HTML | 静态托管集成测试与实际 HTTP 检查 |

## 3. 数据库验收

- migration 可在空库重复部署并明确失败或安全跳过；
- users、refresh_tokens、security_audit_logs、client_behavior_events 的约束、索引和外键生效；Migration 5 执行后不存在 `user_logs`；
- uid/username 按规范化值唯一，且创建时必须且只能存在一个；
- 日志不可通过业务 API 修改或删除；
- 数据库中没有密码、token 原文、私钥或原始机器标识；
- 备份、恢复和 migration 回滚步骤已在目标环境演练。

## 4. 安全验收

- Argon2id 参数、密码策略、失败锁定阈值和限流策略已冻结并写入配置；
- JWT 固定算法、issuer、audience、过期时间和密钥来源；
- refresh token 只保存 hash，支持轮换、撤销和重放检测；
- 所有接口使用 HTTPS，错误响应不泄露账号、权限和内部异常细节；
- 日志、前端共享状态和浏览器持久化存储未发现密码、token、私钥；表单和一次性凭据关闭后已清除。

## 5. 测试门禁

提交前至少运行：

```text
数据库 migration 测试
RBAC policy 单元测试
认证与 token 集成测试
用户生命周期并发测试
API 契约测试
Admin/Client 最小 E2E 测试
```

验收记录必须列出测试版本、数据库版本、配置摘要、命令、结果和未关闭风险。未满足任一 F-01～F-19 的项目不得标记为第一阶段完成。RBAC 服务、migration、Admin 前端、CryptoService 依赖能力和测试代码缺一不可；只有文档不能通过第一阶段验收。
