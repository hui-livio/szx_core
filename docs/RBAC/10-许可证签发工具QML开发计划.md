# 许可证签发工具 QML 图形版实现说明与后续计划

## 1. 背景与目标

当前 `szx_license_issuer` 通过子命令和参数完成密钥生成、请求文件生成、许可证签发、密钥信息查看和许可证验证。命令行方式适合自动化，但在人工签发场景中存在参数多、路径容易填错、错误信息不直观、密钥和有效期配置缺少可视反馈等问题。

图形签发工具复用现有 `szx::crypto`、`szx::license` 和 common 文件工具，不改变许可证格式、加密封装、公共库 API 或命令行工具行为。请求文件生成属于客户端业务 demo，不纳入签发工具主流程；客户端示例单独演示如何调用 `createRequestFile`。签发工具面向受控的发行环境，私钥只通过文件选择器读取，不在界面日志和状态栏中显示密钥内容。

建议目标名称：`szx_license_issuer_gui`。

## 当前实现状态

当前目标 `szx_license_issuer_gui` 已完成密钥管理、许可证签发和许可证验证主流程，并与 `szx_license_issuer` 共用 `szx::crypto`、`szx::license` 和 common 文件能力。密钥记录保存在 Qt `AppDataLocation/datasets`：

```text
datasets/
  key-records.json
  <project-id>/
    <key-id>.pri
    <key-id>.pub
```

已实现：

- 生成 RSA-3072 密钥对，只需项目 ID 和密钥 ID；
- 导入 PEM/DER 密钥对并统一保存为 PEM；
- 项目 ID + 密钥 ID 组合查询、编辑、删除，编辑时同步归档文件；
- `.szxreq` 请求文件签发、永久/定时许可证和许可证验证；
- 对话框、表格和操作列使用 UIToolkits 组件；
- 文件记录使用 JSON 原子保存，`createdAt` 使用 UTC Unix 秒时间戳。

请求 demo 仍位于独立的 `szx_license_user_demo`，不放入签发 GUI。完整命令行链路和错误案例见[软授权工具实现说明](09-软授权工具实现说明.md)。

## 2. 功能梳理

### 2.1 密钥管理

- 生成 RSA-3072 密钥对；填写项目 ID 和密钥 ID，文件自动保存到 `datasets/<project-id>/<key-id>.pri|pub`。
- 支持覆盖前确认，默认禁止覆盖已有文件。
- 导入 DER/PEM 公钥和私钥；Crypto 基础库自动识别并规范化为 PEM。
- 表格展示项目 ID、密钥 ID、公钥路径和操作按钮，支持查询、编辑和删除。
- 私钥内容不显示在界面中；操作完成后清理内存中的私钥字节。

### 2.2 客户端请求示例（独立 demo，不属于签发 GUI）

- 填写产品 ID、应用版本。
- 填写请求功能列表和自定义字段。
- 选择 issuer 公钥。
- 该能力由客户端示例程序提供，而不是签发 GUI 的页面。
- 示例填写产品 ID、应用版本，调用 `createRequestFile` 生成 `.szxreq`。
- 示例只展示生成成功/失败状态和输出路径，不展示原始机器标识。
- 示例使用发行方公钥，但不需要、也不能接触发行方私钥。

### 2.3 许可证签发

- 选择 `.szxreq` 请求文件。
- 选择 issuer 私钥、公钥。
- 配置许可证 ID、issuer、功能列表、自定义字段。
- 配置签发时间、`not_before` 和有限期；支持永久许可证。
- 选择 `.szxlic` 输出路径并签发。
- 在签发前显示摘要确认：产品、版本、许可证 ID、issuer、有效期、功能数量和请求文件路径。
- 签发成功后展示许可证 Key ID、输出文件和下一步操作。

### 2.4 许可证验证

- 选择许可证文件和 issuer 公钥。
- 可选填写预期产品 ID。
- 显示签名、产品、版本、issuer、许可证 ID、有效期、功能、机器因子匹配结果和自定义字段。
- 将错误分为文件错误、格式错误、签名错误、产品不匹配、机器不匹配、未生效和已过期。
- 支持复制验证摘要，不复制私钥或原始机器信息。

### 2.5 操作记录与辅助能力（部分规划）

- 页面级状态提示、进度指示和可关闭的错误详情对话框。
- 最近使用的非敏感路径可选持久化；私钥内容、口令和机器原始标识不得持久化。
- 拖放请求/许可证/密钥文件和英文翻译上下文暂属后续体验工作。

## 3. 界面排版规划

采用单窗口、左侧导航、右侧工作区布局，复用 `UIToolkits` 的 `UTAppWindow`、`UTTitleBar`、`UTCard`、`UTButton`、`UTLineEdit`、`UTDialog`、`UTToast` 等组件。

```text
┌──────────────────────────────────────────────────────────────┐
│ 标题栏：SZX 许可证签发工具                         最小化/关闭 │
├───────────────┬──────────────────────────────────────────────┤
│ 工作区导航     │ 页面标题                         状态/帮助     │
│                 ├──────────────────────────────────────────────┤
│ 主页            │                                              │
│ 密钥管理        │              当前功能卡片区                   │
│ 签发许可证      │                                              │
│ 验证许可证      │                                              │
│                 ├──────────────────────────────────────────────┤
│                 │ 底部状态栏：就绪/处理中/成功/失败             │
└───────────────┴──────────────────────────────────────────────┘
```

### 3.1 主页

提供三个操作卡片：密钥管理、签发许可证、验证许可证；显示最近一次操作结果和工具版本。客户端请求生成由独立业务 demo 提供，不放入签发 GUI。主页不显示密钥内容。

### 3.2 密钥管理页

上方为“导入密钥对”和“生成密钥对”操作；主体使用表格展示项目 ID、密钥 ID、公钥路径和操作按钮。生成对话框只填写项目 ID、密钥 ID，文件自动归档到 `datasets/<project-id>/<key-id>.pri|pub`；导入对话框选择私钥、公钥路径并自动保存为 PEM。私钥内容不展示在界面中。

### 3.3 签发许可证页

采用分步卡片：

1. 请求文件和密钥；
2. 许可证元数据；
3. 功能与自定义字段；
4. 有效期；
5. 摘要确认与签发。

永久许可证使用明确的开关；关闭后显示日期选择器。签发按钮在必填项和公私钥匹配通过前保持禁用。

### 3.4 验证许可证页

左侧选择许可证、公钥和预期产品；右侧使用状态徽章和分组信息展示验证结果。签名无效、机器不匹配等失败原因使用明确的错误颜色和错误码，不仅显示底层异常文本。

## 4. 技术架构

### 4.1 分层

- `qml/`：页面、表单、导航、对话框和状态展示，只负责交互和展示。
- `src/IssuerGuiController.h/.cc`：QObject 控制器，暴露 QML 属性、命令和信号。
- `src/KeyFileHelper.h/.cc`：密钥文件读取、格式识别和 PEM 规范化。
- `szx::license`：请求文件、签发、验证和机器因子业务能力。
- `szx::crypto`：RSA 密钥、PEM/DER、Key ID 等密码学能力。
- common：文件读取、时间、路径和日志辅助。

### 4.2 QML/C++ 边界

- QML 只传递字符串、布尔值、整数和字符串列表，不暴露 `Result<T>`、OpenSSL 类型或第三方 JSON 类型。
- 控制器方法统一返回 `bool`/状态属性，并通过 `operationFinished(success, errorCode, message)` 通知结果。
- C++ 控制器捕获所有异常，将失败映射为稳定的授权错误码；异常不得穿过 Qt/QML 边界。
- 私钥字节仅存在于 C++ 局部对象或受控 worker 生命周期内，操作完成后清零可写缓冲区。
- 所有输出文件使用现有原子写入策略，生成失败不得留下半成品。

### 4.3 线程与交互

- 文件选择、表单编辑和页面切换运行在 GUI 线程。
- 当前密钥生成、签发和验证通过控制器同步调用库 API；操作期间使用 `busy` 状态锁定相关按钮，并在 Qt/QML 边界捕获异常。
- worker 线程、取消和进度反馈属于后续性能优化项；若引入 worker，必须保持现有 Result 错误契约和对象生命周期约束。

## 7. 风险与决策

- GUI 不直接实现密码学逻辑，避免与 `szx_crypto` 产生第二套实现。
- 不在 GUI 内保存 issuer 私钥；每次操作通过文件选择读取，后续如需 Windows 证书库或 TPM 再单独立项。
- 最近路径功能默认关闭或仅保存公钥、请求和许可证路径；私钥路径是否保存需由发行环境策略决定。
- 第一版不引入数据库、网络服务或在线激活，保持离线签发模型。
- 第一版不替换现有 CLI；CLI 继续作为脚本化和 CI 场景入口。
