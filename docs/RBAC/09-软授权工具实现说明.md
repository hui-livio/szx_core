# 软授权工具实现说明

文档对应当前仓库实现（2026-09-09）。软授权采用离线签名模式，客户侧只需要发行方公钥，签发方私钥只在受控发行环境使用。

```text
szx_license_user_demo request
        │  .szxreq（加密请求）
        ▼
szx_license_issuer issue
        │  .szxlic（签名许可证）
        ▼
szx_license_user_demo verify
```

## 能力边界

当前实现的 `.szxreq` 是 SZX 自定义许可证请求封装，不是 PKCS#10/X.509 证书请求（CSR）。`.szxlic` 是 SZX 许可证文件，也不是 X.509 证书。

客户侧公共库 `szx::license` 提供：

- `createRequest`：生成未加密的 UTF-8 请求 JSON。
- `createRequestFile`：采集机器因子并生成加密 `.szxreq` 文件。
- `verify` / `verifyFile`：校验许可证格式、发行方 Key ID、RSA-PSS-SHA256 签名、产品、机器因子和有效期，并返回 `LicenseInfo`。
- `hasFeature`：检查许可证是否包含指定功能码。

签发端 API 位于内部头文件 `SzxLicense/Issuer.h`，不随客户安装包发布：

- `issue`：根据已解密请求 JSON 创建许可证封装。
- `issueFile`：读取并解密 `.szxreq`，校验请求后创建许可证封装。

所有跨库调用均通过 `SZX::COMMON::Result<T>` 返回结果，时间字段使用 UTC Unix 秒时间戳。

## 文件格式和安全属性

### `.szxreq`

- 文件头为 `SZXR`，版本 1。
- 使用 RSA-OAEP-SHA256 包装随机 AES-256-GCM 会话密钥。
- 加密内容为 Iguana 序列化的 UTF-8 请求 JSON，包含产品、版本、请求 ID、创建时间、机器因子摘要、请求功能和自定义字段。
- 不包含原始硬件标识、发行私钥或密码。
- 只有持有对应发行私钥的 `szx_license_issuer issue` 才能解密。

### `.szxlic`

- 文件头为 `SZXL`，版本 1。
- 签名算法为 RSA-PSS-SHA256。
- 签名覆盖 Key ID、payload 长度和 payload 原始字节；Key ID 为发行方公钥 SHA-256 摘要。
- payload 包含许可证 ID、产品、版本、发行方、签发/生效/到期 UTC 时间、功能、机器因子摘要和自定义字段。
- `expires_at` 为空表示永久许可证；设置为 UTC Unix 秒时间戳表示到期时间。

机器因子在产品域内进行 SHA-256 哈希。Windows 当前采集 SMBIOS UUID、MachineGuid 和系统卷序列号；Linux 当前采集 `/etc/machine-id`。验签时最多允许 8 个因子；许可证包含 1 个因子时要求匹配 1 个，包含 2 个及以上因子时默认至少匹配 2 个不同因子。

## CLI 使用

两个工具均使用 CLI11 子命令解析。可执行文件通常位于 `build/bin/`（多配置构建位于对应配置子目录）。

### 1. 生成发行方 PEM 密钥

```powershell
szx_license_issuer keygen `
  --private-key issuer-private.pem `
  --public-key issuer-public.pem
```

生成 RSA-3072、未加密 PKCS#8 PEM 私钥和 SubjectPublicKeyInfo PEM 公钥。已有文件默认不覆盖，确需覆盖时显式添加 `--force`。

### 2. 客户端生成请求

```powershell
szx_license_user_demo request `
  --product szx.crypto-tool `
  --version 1.0 `
  --public-key issuer-public.pem `
  --output machine.szxreq
```

客户端只读取发行方公钥；公钥支持 PEM 或 DER，Crypto 基础库会自动识别并规范化。请求文件生成后交给发行方，不能使用客户端 demo 自行签发。

### 3. 内部签发许可证

```powershell
szx_license_issuer issue `
  --request machine.szxreq `
  --private-key issuer-private.pem `
  --public-key issuer-public.pem `
  --output customer.szxlic `
  --license-id lic-001 `
  --issuer internal `
  --days 365
```

`--days` 省略时生成永久许可证；指定时必须为正整数。`--license-id` 和 `--issuer` 省略时使用工具默认值。签发前会校验请求格式、私钥解密、公私钥匹配和许可证期限，签名后还会使用公钥自验。

### 4. 查看公钥 Key ID

```powershell
szx_license_issuer key-info --public-key issuer-public.pem
```

### 5. 验证许可证

```powershell
szx_license_user_demo verify `
  --input customer.szxlic `
  --public-key issuer-public.pem `
  --product szx.crypto-tool
```

验证成功时输出许可证 ID、产品、版本、发行方、UTC 时间、功能和机器因子数量；产品参数可省略，省略后不执行产品匹配。验证失败返回非零退出码。

## 错误和测试

库层稳定错误码定义在 `SzxLicense/License.h`，包括格式错误、版本不支持、签名无效、过期、尚未生效、产品不匹配、机器不匹配和 I/O 错误。CLI11 负责必填参数、未知参数和数字参数解析；业务错误通过非零退出码返回。

运行完整 CLI 端到端测试：

```powershell
py -3 scripts/test_license_flow.py
```

脚本会创建临时 RSA 密钥，依次调用客户端请求 demo、发行方签发 CLI 和客户端验证 demo，并检查以下失败场景：错误产品、篡改许可证、损坏请求和非法 `--days` 参数。测试通过时输出：

```text
PASS: license request, issue, verify, and error-case tests
```

## 当前限制

- 当前格式是 SZX 私有许可证协议，不提供标准 CSR 或 X.509 证书链。
- 许可证默认绑定机器因子；更换机器或机器标识变化可能导致 `MachineMismatch`，需要重新签发。
- 尚未实现许可证安装存储、时钟回拨保护、在线吊销和发行方公钥轮换策略。
- 私钥文件由发行工具按路径读取；不支持加密 PEM 私钥，私钥不得进入客户包、日志或测试资产。
