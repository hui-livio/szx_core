# 单项目 RBAC Admin 前端设计

## 1. 技术栈

Vue 3 + TypeScript + Vite、Vue Router、Pinia、Axios。第一阶段不引入复杂权限编辑器。

实现位于 `tools/szx_admin/web/admin`，采用 MVVM：`pages/components` 负责展示和绑定，`composables/use*ViewModel.ts` 负责界面行为与表单流程，`stores` 保存共享状态，`api` 负责类型化接口与会话传输。运行、测试说明见 [前端 README](../../tools/szx_admin/web/admin/README.md)，服务部署见 [Admin 部署与使用指南](12-Admin部署与使用指南.md)。

## 2. 页面

下列路径为应用内路由；开发环境位于 `/`，生产地址统一加 `/admin` 前缀，例如 `/admin/login`。

- `/login`：UID/用户名登录。
- `/change-password`：首次登录和自助改密。
- `/users`：用户列表、创建、编辑、启用/禁用、解锁、重置密码、角色分配；管理员只能创建/管理 operator/engineer，超管才显示独立的角色分配操作。
- `/logs`：安全审计和用户行为查询，两个页签分别读取 `/admin/audit-logs` 与 `/admin/behavior-events`。
- `/home`：业务首页，根据角色展示可用入口。

正常登录后，四种角色统一默认进入 `/home`；用户管理、审计和机器性能按权限从侧栏/首页入口进入。强制改密及密码推荐流程保持原样，跳过推荐后同样进入 `/home`。第一阶段不提供项目切换器、平台管理页、权限组页面。

## 3. 用户表单

创建用户时 `uid` 与 `username` 必须且只能填写一个，前端使用互斥输入控件并在提交前校验；身份标识创建后不可修改。管理员只能看到并选择操作员/工程师，超管才能选择管理员/超管。后端校验失败时展示稳定错误码。

创建表单可指定初始密码并确认，按目标角色校验：操作员/技术员（engineer）至少 6 个字符，不要求字母数字组合；管理员/超级管理员至少 8 个字符且包含字母和数字。自助改密按当前登录角色使用同一规则，新密码必须填写；只有创建用户和重置密码时留空才自动生成临时密码。校验、摘要和清理在 ViewModel 中处理，组件只负责绑定；指定密码以 `password_hash` 提交，成功后直接关闭创建窗口，不展示临时凭据。成功、取消或离开页面清空密码，不写入共享状态或浏览器存储。

重置密码支持手动指定并确认，按目标角色校验；留空则随机生成 20 字符临时密码，默认 24 小时有效。手动指定时不回显密码、不设置临时凭据有效期，首次改密策略不变。重置自己的密码后重新登录；随机重置时先展示一次临时凭据，确认记录后退出。服务端只接收 SHA-256 摘要，不能据此校验原始密码长度或字符组合。

## 4. 前端权限

Pinia 保存当前用户和单角色信息；路由守卫按固定角色映射控制菜单。前端隐藏按钮不视为安全措施，接口返回 401/403 时统一处理。列表支持分页、搜索、空状态、防重复提交和版本冲突提示。用户状态显示 active/disabled/locked，锁定用户不能通过普通编辑操作绕过解锁策略。

登录成功先读取 `data.user`：超管的 `force_password_change=true` 时必须进入改密流程，不显示跳过；非超管的 `password_change_recommended=true` 时显示改密提示及“跳过”按钮，允许直接进入业务。跳过仅影响当前客户端流程，不发送改密请求，不清除服务端待改密标记；再次登录仍可提示。改密提交旧/新密码的 SHA-256 小写摘要、Bearer token 和当前用户 If-Match；成功后清除旧会话并重新登录。

当前已接入 `GET /client/me/permissions`，Pinia 保存角色、能力、状态和 `authz_version`，通过 `can('business.operate')` 判断界面能力。该接口只返回 `force_password_change`；`password_change_recommended` 从登录/刷新返回的 User 读取。

会话逻辑集中在 `src/api/client.ts`：

- 请求前 access token 已过期或剩余有效期不超过 5 秒时先刷新；普通请求返回 `401 / 2200` 或 `401 / 2201` 时刷新后最多重试一次。
- 同一页面的并发刷新合并为一个请求，携带 refresh Cookie 和 `X-CSRF-Token`；成功后替换内存中的 access/CSRF。页面闲置时没有定时刷新；默认连续空闲超过 30 分钟后 refresh 失效，恢复操作时回到登录页。成功刷新重置空闲窗口，但不延长默认 7 天的会话族绝对期限。
- refresh 返回 401、403 或错误码 2202（包括 `409 / 2202` 重放）时清空内存会话；重试后仍返回上述 access 鉴权错误时同样清空。429/5xx 和网络故障保留会话，提示手动重试，不盲目重放写请求。
- 登出携带 Cookie 和 CSRF，收到成功 204 后才清除本地会话。
- access/CSRF 保存在 API 客户端闭包，refresh token 通过 HttpOnly、Secure、SameSite Cookie 管理，不写入 localStorage/sessionStorage。刷新页面后重新登录，当前不做跨标签页会话同步。

## 5. 错误与审计展示

- 普通请求的 access token 过期先刷新，最终失效时回到登录页。业务请求的 `403 / 2204` 保留页面并提示无权限，`409 / 2209` 要求重新加载；refresh 的 403 和 `409 / 2202` 按上节清空会话。
- 登录失败不显示“用户不存在/密码错误”的差异。
- 用户创建、状态变更、角色变更、重置密码和查看审计日志后显示 request_id，便于定位服务端记录。
- 审计详情只展示脱敏字段，不展示密码、token、私钥和原始机器标识。
- 操作者显示用户名，UID 账号显示 UID，未关联用户显示“未知用户”；用户搜索使用 `actor_search` 同时匹配展示名、用户名和 UID，不提供内部 UUID 输入。匹配、分页和总数统计均在后端完成。
- 事件名称使用 `event_search` 搜索中文名称或事件代码关键词，去除首尾空白并重置到第一页；由服务端完成匹配、分页及总数统计，清空后取消事件过滤。
- 事件名称使用可编辑的 LuminaSelect：安全审计提供本地化名称及对应事件代码，选中预设后通过 event_search 提交稳定代码，也允许自由输入名称/代码关键词；行为事件候选项从当前返回记录中去重提取，不限制未知代码的手工查询。两种输入沿用主题弹出层、圆角、focus 描边和滚动条，不使用原生 datalist。“重置筛选”清空全部条件并重新加载第一页。
- 用户列表禁用对自己的角色分配和禁用操作；高于自身或超出管理范围的目标不可操作。ViewModel 计算权限并在提交前校验，后端依据数据库中的当前角色再次授权，拒绝时返回 `403 / 2204`。
- 创建用户或重置密码得到的一次性临时凭据只在成功响应后展示一次，页面关闭或刷新后不可恢复，不写入 Pinia、localStorage、日志或最近路径。

### 查看角色与权限关联

`/roles` 提供独立的“角色与权限”只读页，按 `role.read` 显示侧栏入口，Home 增加“查看角色权限关联”链接。可查看不同角色的完整权限集合、关联数量及当前生效状态，包含内置、自定义和停用权限；可选择停用/归档角色。`/home` 仍只展示当前账号权限，不承担全局角色关联目录。

权限详情需要 `permission.read`；缺少该能力时仅展示关联 ID。只读查看不要求分配权限，写操作仍从 `/permissions` 页面进行。页面复用既有角色/权限 GET 接口，支持刷新、过滤、并发版本冲突提示和快速切换时的旧响应隔离。
