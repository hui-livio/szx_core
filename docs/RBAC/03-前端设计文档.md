# 单项目 RBAC Admin 前端设计

## 1. 技术栈

Vue 3 + TypeScript + Vite、Vue Router、Pinia、Axios。第一阶段不引入复杂权限编辑器。

## 2. 页面

- `/login`：登录、首次登录改密。
- `/users`：用户列表、创建、编辑、启用/禁用、解锁、重置密码、角色分配；管理员只能创建/管理 operator/engineer，超管才显示独立的角色分配操作。
- `/logs`：用户行为和安全日志查询。
- `/home`：业务首页，根据角色展示可用入口。

管理员和超管默认进入 `/users`；操作员和工程师进入业务首页。第一阶段不提供项目切换器、平台管理页、权限组页面。

## 3. 用户表单

创建用户时 `uid` 与 `username` 必须且只能填写一个，前端使用互斥输入控件并在提交前校验；身份标识创建后不可修改。管理员只能看到并选择操作员/工程师，超管才能选择管理员/超管。后端校验失败时展示稳定错误码。

## 4. 前端权限

Pinia 保存当前用户和单角色信息；路由守卫按固定角色映射控制菜单。前端隐藏按钮不视为安全措施，接口返回 401/403 时统一处理。列表支持分页、搜索、空状态、防重复提交和版本冲突提示。用户状态显示 active/disabled/locked，锁定用户不能通过普通编辑操作绕过解锁策略。

登录成功后调用 `GET /client/me/permissions`，将 `role`、`capabilities`、`status`、`force_password_change` 和 `authz_version` 缓存在 Pinia，并通过 `can('business.operate')` 判断界面能力。`force_password_change=true` 时只允许进入改密流程、登出和刷新 token；完成改密后再进入业务页面。access token 过期时 Axios 只允许一个并发 refresh 请求，成功后重放原请求；refresh 失败或重放检测失败才清空会话并跳转登录。refresh token 不写入不受保护的 localStorage，浏览器实现使用 HttpOnly、Secure、SameSite Cookie，并配套 CSRF 防护。

## 5. 错误与审计展示

- refresh 失败后的 401 才跳转登录并清空本地会话；正常 access token 过期先执行一次 refresh。403 保留当前页面并展示无权限提示；409 展示版本冲突并要求重新加载。
- 登录失败不显示“用户不存在/密码错误”的差异。
- 用户创建、状态变更、角色变更、重置密码和查看审计日志后显示 request_id，便于定位服务端记录。
- 审计详情只展示脱敏字段，不展示密码、token、私钥和原始机器标识。
- 创建用户或重置密码得到的一次性临时凭据只在成功响应后展示一次，页面关闭或刷新后不可恢复，不写入 Pinia、localStorage、日志或最近路径。
