# 单项目 RBAC Admin 前端设计

## 1. 技术栈

Vue 3 + TypeScript + Vite、Vue Router、Pinia、Axios。第一阶段不引入复杂权限编辑器。

实现位于 `RBAC/szx_admin_web`，采用 MVVM：`pages/components` 负责展示和绑定，`composables/use*ViewModel.ts` 负责界面行为与表单流程，`stores` 保存共享状态，`api` 负责类型化接口与会话传输。运行、测试和部署说明见该项目 README。

## 2. 页面

- `/login`：登录、首次登录改密。
- `/users`：用户列表、创建、编辑、启用/禁用、解锁、重置密码、角色分配；管理员只能创建/管理 operator/engineer，超管才显示独立的角色分配操作。
- `/logs`：用户行为和安全日志查询。
- `/home`：业务首页，根据角色展示可用入口。

管理员和超管默认进入 `/users`；操作员和工程师进入业务首页。第一阶段不提供项目切换器、平台管理页、权限组页面。

## 3. 用户表单

创建用户时 `uid` 与 `username` 必须且只能填写一个，前端使用互斥输入控件并在提交前校验；身份标识创建后不可修改。管理员只能看到并选择操作员/工程师，超管才能选择管理员/超管。后端校验失败时展示稳定错误码。

创建表单可指定初始密码并确认，按目标角色校验：操作员/技术员（engineer）至少 6 个字符，不要求字母数字组合；管理员/超级管理员至少 8 个字符且包含字母和数字。修改密码时按当前登录角色使用同一规则；留空则自动生成临时密码。校验、摘要和清理在 ViewModel 中处理，组件只负责绑定；指定密码以 `password_hash` 提交，成功后直接关闭创建窗口，不展示临时凭据。成功、取消或离开页面清空密码，不写入共享状态或浏览器存储。

## 4. 前端权限

Pinia 保存当前用户和单角色信息；路由守卫按固定角色映射控制菜单。前端隐藏按钮不视为安全措施，接口返回 401/403 时统一处理。列表支持分页、搜索、空状态、防重复提交和版本冲突提示。用户状态显示 active/disabled/locked，锁定用户不能通过普通编辑操作绕过解锁策略。

登录成功先读取 `data.user`：超管的 `force_password_change=true` 时必须进入改密流程，不显示跳过；非超管的 `password_change_recommended=true` 时显示改密提示及“跳过”按钮，允许直接进入业务。跳过仅影响当前客户端流程，不发送改密请求，不清除服务端待改密标记；再次登录仍可提示。改密提交旧/新密码的 SHA-256 小写摘要、Bearer token 和当前用户 If-Match；成功后清除旧会话并重新登录。

后续权限接口接入后调用 `GET /client/me/permissions`，将 `role`、`capabilities`、`status`、两个改密标记和 `authz_version` 缓存在 Pinia，并通过 `can('business.operate')` 判断界面能力。access token 过期时 Axios 只允许一个并发 refresh 请求，携带 `credentials: include` 和当前 X-CSRF-Token；成功后更新内存中的 access/CSRF 再重放原请求。refresh 401 或重放 409 时清空会话并跳转登录；429/5xx 不视为已登出，遵循重试策略。登出调用 POST /auth/logout，携带 Cookie 和 CSRF，成功 204 后清除本地会话。refresh token 不写入不受保护的 localStorage，浏览器实现使用 HttpOnly、Secure、SameSite Cookie。目前服务端和前端已接入登录/改密/刷新/登出及权限查询。前端 access/CSRF 仅在内存中保存，页面刷新后重新登录；当前未实现跨标签页会话同步。

## 5. 错误与审计展示

- refresh 失败后的 401 才跳转登录并清空本地会话；正常 access token 过期先执行一次 refresh。403 保留当前页面并展示无权限提示；409 展示版本冲突并要求重新加载。
- 登录失败不显示“用户不存在/密码错误”的差异。
- 用户创建、状态变更、角色变更、重置密码和查看审计日志后显示 request_id，便于定位服务端记录。
- 审计详情只展示脱敏字段，不展示密码、token、私钥和原始机器标识。
- 事件名称使用 `event_search` 搜索中文名称或事件代码关键词，去除首尾空白并重置到第一页；由服务端完成匹配、分页及总数统计，清空后取消事件过滤。
- 事件名称输入框提供中文名称候选项及对应代码，也允许自由输入关键词；“重置筛选”清空全部条件并重新加载第一页。
- 用户列表禁用对自己的角色分配和禁用操作；高于自身或超出管理范围的目标不可操作。ViewModel 计算权限并在提交前校验，后端依据数据库中的当前角色再次授权，拒绝时返回 `403 / 2204`。
- 创建用户或重置密码得到的一次性临时凭据只在成功响应后展示一次，页面关闭或刷新后不可恢复，不写入 Pinia、localStorage、日志或最近路径。
