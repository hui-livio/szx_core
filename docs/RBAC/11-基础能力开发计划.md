# RBAC 基础能力开发计划

## 1. 实施边界

第一阶段代码统一放在当前仓库：

```text
RBAC/
  CMakeLists.txt
  szx_admin/       # C++ 后端与基础服务能力
  szx_admin_web/   # Vue 3 + TypeScript + Vite Admin
```

当前不拆分仓库。后端通过 HTTP API 对外提供 RBAC 能力，现有业务客户端只依赖 API 契约和后续适配层。

开发负责人：项目负责人本人。

## 2. 固定依赖

| 依赖 | 版本 | 来源 | 用途 |
|---|---|---|---|
| libhv | v1.3.4 | GitHub release ZIP | HTTP/HTTPS、路由和事件循环 |
| jwt-cpp | v0.7.2 | GitHub release ZIP | JWT 协议解析和构建；签名通过 CryptoService |
| ormpp | 仓库固定版本 | `third_party/ormpp` | MySQL 数据访问 |
| MySQL | 8.0+ | 本地/部署环境 | 持久化数据库 |
| Vue | 3.x | 本地 Node 环境 | Admin 前端 |

依赖 ZIP 的 SHA-256、许可证和本地目录记录在[三方库评审](07-C++三方库评审.md)及仓库依赖清单中。升级依赖时必须重新记录版本、哈希并执行回归测试。

## 3. 阶段计划

### 阶段 0：依赖与环境验证

- 验证 libhv、jwt-cpp ZIP 源码可被当前 CMake/MSVC 构建。
- 验证 ormpp 自动发现本地 MySQL C API。
- 完成 MySQL 连接、事务、参数绑定和连接失败测试。
- 固定 Node、Vue、Vite、TypeScript 和包管理器版本。
- 记录 Debug/Release、x64、运行库和 OpenSSL 配置。

出口：后端空 target 和前端空项目均可构建；MySQL 最小连接测试通过。

### 阶段 1：基础能力

按以下顺序实现：

1. 配置加载和敏感配置来源。
2. 统一错误码、HTTP 错误映射和 request ID。
3. MySQL/ormpp 连接池、事务 RAII 和 migration 执行器。
4. `JwtService`：PS256、claims、`kid`、issuer/audience、时钟偏差和密钥提供接口。
5. 审计日志接口和脱敏策略。
6. HTTP transport、中间件和健康检查。
7. Vue API Client、Pinia 会话状态和路由守卫。

当前已完成的 JWT 基础能力：

- `JwtService` 支持 PS256、固定 claims、`kid`、issuer/audience、时钟偏差和稳定错误码；
- `JwtKeyStore` 支持内存密钥注册、当前签名密钥激活、按 `kid` 验证和旧密钥有效期；
- `JwtConfig` 仅保存配置数据，由后续主程序统一解析全局配置并注入。

当前已完成的基础设施能力：

- `ServerConfig` 支持 HTTP host、port、worker、请求体上限、连接上限、API prefix 和访问日志配置；
- `ErrorCode` 统一维护 API 错误码、HTTP 状态映射和安全默认消息；
- `RequestContext` 规范化或生成 `X-Request-ID`，并保证响应回传 request ID；
- `HttpTransport` 隔离 libhv 类型，提供路由注册、启动/停止、请求体限制、统一错误响应和 `/api/v1/health` 健康检查；
- `ServerConfig` 和 `DatabaseConfig` 仅保存并校验配置数据，不自行读取文件或环境变量；后续由主程序统一解析全局配置后注入；`DatabasePool` 通过 ormpp 管理连接、会话参数和事务边界；`MigrationRunner` 校验版本 checksum 并执行 SQL migration；
- 业务 Repository 必须使用 ormpp 的反射实体、查询构造和参数绑定；原生 SQL 仅限审核后的 migration DDL、数据库会话初始化和 MySQL advisory lock，不得作为业务 CRUD 接口下沉。
- `001_initial_schema.sql` 固化 users、refresh_tokens、user_logs 和 schema_migrations 的 MySQL/InnoDB/utf8mb4 基线。

尚未完成的认证业务能力：登录、refresh token family、密码校验、bootstrap 超管、持久化密钥存储和生产密钥托管。这些属于阶段 2 或部署安全工作，不在本次 JWT 基础能力范围内。

出口：基础 target 可构建；JwtService 单测通过；错误、日志和数据库边界不泄漏异常。

### 阶段 2：认证与会话

- Argon2id 密码策略和 rehash 判断；
- bootstrap 超管初始化；
- 登录、首次改密和自助改密；
- access token 校验；
- refresh token hash、轮换、family 重放和登出；
- 失败计数、锁定、限流和会话失效。

出口：认证 API 集成测试、refresh 并发测试和安全审计测试通过。

### 阶段 3：用户与 Policy

- users migration 和 Repository；
- 四角色能力矩阵；
- 用户创建、编辑、启停、解锁和密码重置；
- `If-Match` 乐观锁；
- 最后一个 active 超管事务保护；
- `GET /client/me/permissions`。

出口：四角色 × API 的正反向权限矩阵测试通过。

### 阶段 4：Admin Web 与最小业务闭环

- 登录和首次改密页面；
- 用户列表、创建、编辑和状态操作；
- 权限菜单和按钮控制；
- 日志查询页面；
- 至少一条 Client 业务接口端到端验证。

出口：浏览器主流程、401/403/409、refresh 并发和后端越权测试通过。
